# 単一SQLiteと名前付きライブラリの設計

## 対象と目的

本設計は、BookCafeの永続化を一つのSQLiteへ集約し、名前付きの複数ライブラリをWeb UIから管理できるようにする。

従来の`DataDir`と`Collection Root`は、保存場所とスキャン対象という異なる責務を表していた。

本設計では、ユーザーが操作する保存単位を**ライブラリ**へ統一する。

一つのライブラリは、一つの名前と一つの対象ディレクトリを持つ。

対象ディレクトリ内の原本には、BookCafeの管理ファイルを追加しない。

認証情報、ライブラリ情報、蔵書、読書進捗、ジョブ、分類に使うメタデータは、共通状態ディレクトリに置く一つのSQLiteへ保存する。

サムネイルは再生成可能なデータとして共通状態ディレクトリへ保存し、SQLiteには参照情報だけを保存する。

## 用語

- **状態ディレクトリ**：BookCafeが共通設定、SQLite、サムネイル、キャッシュ、ログを保存する内部ディレクトリ。
- **ライブラリ**：名前と対象ディレクトリを持つ、ユーザーが切り替える蔵書単位。
- **対象ディレクトリ**：ライブラリがスキャンする一つのサーバー側ディレクトリ。
- **本**：対象ディレクトリから検出し、ライブラリからの相対パスで識別する蔵書レコード。
- **ページ**：本の原本から導出した、順序付きの表示単位。
- **アーカイブ**：本を通常一覧、通常検索、スキャン、分類から除外し、復元可能な状態で保持する操作。

ユーザー向けUIと内部モデルでは`DataDir`と`Collection Root`を使用しない。

設定やコードで共通保存場所を指す必要がある場合だけ、`StateDir`という名前を使用する。

## 対象範囲

本変更の対象は次の機能である。

- 共通状態ディレクトリと単一SQLiteへの移行
- Better Authのユーザーとセッションの共通SQLite保存
- 初期設定からライブラリ設定を分離
- 名前付きライブラリの登録、更新、削除
- ユーザーごとの選択中ライブラリ
- ライブラリ単位の蔵書一覧、検索、スキャン、ジョブ
- 絶対パスからライブラリ相対パスへの蔵書モデル変更
- 本のアーカイブと復元
- ページ一覧の相対参照
- ユーザーごとの読書位置
- サムネイルの共通状態ディレクトリ保存
- Web UIのライブラリ選択とライブラリ管理
- Desktop ManagerとWeb初期設定からの`DataDir`入力削除
- READMEの用語、設定例、Linux運用手順の更新

自動分類器の選定、分類アルゴリズム、外部AIサービス連携は本変更に含めない。

現在の手動タグ、読書状態、書誌情報は本に所属するため、ライブラリ境界の内側へ保存される。

将来追加する自動分類ジョブと分類結果も`library_id`を必須とする。

本や画像のリネームを内容から推定し、以前のレコードとの対応候補を表示する機能は本変更に含めない。

## 保存構成

状態ディレクトリの構成は次のとおりとする。

```text
BookCafe StateDir/
├─ config.json
├─ bookcafe.sqlite
├─ thumbnails/
│  └─ {libraryId}/
│     └─ {bookId}.webp
├─ cache/
└─ logs/
```

SQLiteをWALモードで使用する場合は、実行中に`bookcafe.sqlite-wal`と`bookcafe.sqlite-shm`が同じ場所へ生成される。

対象ディレクトリには、SQLite、サムネイル、キャッシュ、ログ、識別用マーカーファイルを作成しない。

状態ディレクトリはOSごとの既定のアプリケーションデータディレクトリから決定する。

既定値はmacOSで`~/Library/Application Support/BookCafe`、Windowsで`%APPDATA%/BookCafe`、Linuxで`$XDG_DATA_HOME/bookcafe`とする。

`XDG_DATA_HOME`が未設定のLinuxでは`~/.local/share/bookcafe`を使用する。

`BOOKCAFE_STATE_DIR`は状態ディレクトリの既定値を上書きする。

既存環境との互換性のため、`BOOKCAFE_STATE_DIR`が未設定の場合だけ旧`BOOKCAFE_DATA_DIR`を状態ディレクトリ指定として受け付ける。

`config.json`は、サーバーの`host`、`port`、サムネイル生成設定など、SQLiteを開く前に必要な実行設定だけを保持する。

`config.json`は、ライブラリ、選択中ライブラリ、初期設定完了状態を保持しない。

## 初期設定と認証

初期設定は、共通ユーザーの作成だけで完了する。

初期設定フォームと`POST /api/setup/initial-user`から、`dataDir`とライブラリ対象パスを削除する。

初期設定request bodyは`username`と`password`だけを受け取る。

サーバーのネットワーク設定とサムネイル設定は既定値で起動し、ログイン後の設定画面から変更する。

最初のライブラリは、ログイン後のライブラリ画面から登録する。

初期設定完了状態は、共通SQLiteのBetter Auth `user`テーブルにユーザーが存在するかどうかで判定する。

Better Authの`user`、`session`、`account`、`verification`は、蔵書テーブルと同じ`bookcafe.sqlite`へ保存する。

ライブラリを切り替えても、ユーザーとセッションは変化しない。

選択中ライブラリはユーザーごとに保存し、別のブラウザーや別のユーザーによる選択と共有しない。

選択中ライブラリを削除した場合は、外部キーの`ON DELETE SET NULL`で選択を解除する。

Web UIは残っているライブラリの先頭を選択し、その選択をユーザー設定へ保存する。

## ライブラリモデル

`libraries`は次の列を持つ。

```text
libraries
- id
- name
- root_path
- canonical_root_path
- created_at
- updated_at
```

`id`はランダムなUUID文字列とする。

`name`は前後の空白を除去し、空文字を拒否する。

同じ表示名を大文字と小文字だけ変えて重複登録することは拒否する。

`root_path`はユーザーが入力したサーバー側の絶対パスを正規化した値とする。

`canonical_root_path`は、存在するパスのシンボリックリンクを解決し、重複と包含関係の検証に使用する。

同じ物理ディレクトリを複数のライブラリへ登録することは拒否する。

既存ライブラリの親または子に当たるディレクトリを別ライブラリとして登録することも拒否する。

重複スキャンと同一原本の二重登録を防ぐためである。

対象ディレクトリは、登録時と設定変更時に存在、ディレクトリ種別、読み取り権限を検証する。

対象ディレクトリへBookCafeが書き込めることは要求しない。

### ライブラリの操作

ライブラリは次の操作を提供する。

- 登録
- 名前の変更
- 対象ディレクトリの変更
- スキャン
- 削除

対象ディレクトリの変更中にスキャンジョブが待機中または実行中の場合は、`409 LIBRARY_BUSY`で拒否する。

対象ディレクトリを変更しても、自動スキャンは開始しない。

ルートディレクトリの名前だけが変わり、内部の相対パスが変わらなければ、既存の本、読書進捗、タグ、分類情報は同じレコードへ残る。

無関係な対象ディレクトリへ変更した場合は、次回スキャンで存在しない相対パスを`missing`へ変更し、新しい相対パスを新しい本として登録する。

### ライブラリの削除

ライブラリ削除は、対象ライブラリに待機中または実行中のジョブがある場合に`409 LIBRARY_BUSY`で拒否する。

削除はSQLiteトランザクション内で、所属する本、ページ、読書進捗、タグ、ジョブを削除する。

SQLiteの削除が確定した後、共通状態ディレクトリ内のライブラリ用サムネイルを削除する。

サムネイル削除に失敗してもSQLiteトランザクションを戻さず、失敗をログへ記録する。

原本ファイルと対象ディレクトリは変更も削除もしない。

削除後に同じ対象ディレクトリを登録した場合は、新しいライブラリとして扱う。

削除済みライブラリの本、読書進捗、タグ、分類情報は復元しない。

## 蔵書モデル

`books`はライブラリへの外部キーと、ライブラリからの相対パスを持つ。

```text
books
- id
- library_id
- relative_path
- title
- authors_json
- publisher
- isbn
- purchased_at
- reading_status
- tags_json
- notes
- format
- status
- page_count
- reading_direction
- thumbnail_path
- size
- mtime_ms
- fingerprint
- metadata_edited_at
- archived_at
- created_at
- updated_at
```

`id`はランダムなUUID文字列とする。

本のIDを絶対パスのハッシュから生成しない。

`(library_id, relative_path)`へ一意制約を設定する。

同じ相対パスを再スキャンした場合は、同じ本を更新する。

ライブラリの対象ディレクトリが変わっても、相対パスが同じなら本のIDは変化しない。

本や本フォルダーを対象ディレクトリ内で移動またはリネームした場合は、新しい相対パスの本として登録する。

以前の相対パスの本は`missing`となる。

移動前後の本を内容、サイズ、更新日時、画像類似度から自動的に関連付けない。

`fingerprint`は変更検知にだけ使用し、本の同一性判定には使用しない。

既存の手動編集済みメタデータは、同じ本の再スキャンで保持する。

永続化済みの本がない場合にsample bookを返すfallbackは削除する。

ライブラリ未登録または本が0冊の場合は、実データがない状態をそのまま空の一覧として返す。

## 本のアーカイブ

本のアーカイブ状態は`books.archived_at`で表す。

本を削除するAPIとUI操作は提供しない。

アーカイブ済みの本は、通常の本一覧、通常検索、スキャン処理、分類対象から除外する。

アーカイブ一覧では、アーカイブ済みの本だけを表示する。

アーカイブ済みの本は、蔵書レコード、ページ、読書進捗、タグ、分類情報、サムネイルを保持する。

スキャナーは、対象ライブラリのアーカイブ済み相対パスをスキャン開始時に取得する。

画像フォルダーまたはファイル候補の絶対パスを相対パスへ変換し、アーカイブ済み集合に含まれる場合は解析と永続化を行わない。

アーカイブ済みの本を復元するときは、`archived_at`を`NULL`へ戻す。

復元時に自動スキャンは開始しない。

原本が存在しない状態で復元した本は、次回スキャンまたは読み込み失敗によって`missing`として扱う。

アーカイブ中に原本を移動またはリネームした場合、移動後の相対パスは新しい本として検出する。

移動前のアーカイブ済みレコードは自動的に統合しない。

## ページモデル

ページ一覧は、原本から導出したスキャン時点のスナップショットとしてSQLiteへ保存する。

ページの絶対パスは保存しない。

```text
book_pages
- book_id
- page_number
- source_type
- relative_path
- entry_path
- source_page_number
- width
- height
- mime_type
- created_at
```

`(book_id, page_number)`を主キーとする。

`page_number`は1から始まる欠番のない表示順とする。

`source_type`は次の値を取る。

- `file`
- `archive-entry`
- `packed-archive-entry`
- `pdf-page`
- `epub-page`

画像フォルダーでは、本フォルダーからの画像相対パスを`relative_path`へ保存する。

ZIP、CBZ、RAR、CBR、7zでは、圧縮ファイル内の画像パスを`entry_path`へ保存する。

PDFとEPUBでは、アダプターが使用する元ページ番号を`source_page_number`へ保存する。

形式ごとに不要な参照列は`NULL`とする。

スキーマの`CHECK`制約により、`source_type`と必須参照列の組み合わせを検証する。

### ページ一覧の更新

同じ本を再スキャンした場合は、本単位のSQLiteトランザクションでページ一覧を置換する。

処理順序は次のとおりとする。

1. 原本からページ候補を取得する。
2. ページ候補を自然順または形式固有順へ並べる。
3. 既存ページを削除する。
4. 新しいページ一覧を連番で保存する。
5. `books.page_count`を更新する。
6. 読書位置が新しいページ数を超える場合は末尾へ丸める。
7. 全処理が成功した場合だけコミットする。

アーカイブ済みの本はスキャンしないため、ページ一覧も更新しない。

画像の追加、削除、リネームによって順序が変わった場合は、新しい順序を採用する。

旧画像との内容照合や類似画像判定は行わない。

## 読書進捗

ページ一覧は本に所属し、読書位置はユーザーに所属する。

```text
reading_progress
- user_id
- book_id
- current_page
- updated_at
```

`(user_id, book_id)`を主キーとする。

`user_id`はBetter Authの`user.id`を参照する。

`book_id`は`books.id`を参照し、ライブラリ削除時に連鎖削除する。

本の再スキャンでページ数が減った場合は、各ユーザーの`current_page`を新しいページ数の範囲へ丸める。

ページ順が変わっても、画像内容から読書位置を移動しない。

## ジョブとスキャン

`jobs`は`library_id`を必須とする。

```text
jobs
- id
- library_id
- type
- status
- payload
- progress
- error
- created_at
- updated_at
```

スキャンジョブは作成時の`library_id`を保持し、UIで選択中のライブラリが変わっても対象を変更しない。

スキャン開始時にライブラリの対象ディレクトリを読み取り、そのジョブの実行中は固定する。

対象ディレクトリの変更とライブラリ削除は、待機中または実行中のジョブがなくなるまで拒否する。

ライブラリスキャンは対象ディレクトリ全体を走査する。

部分スキャンと複数ルートの個別スキャンは提供しない。

スキャンで検出しなかった通常状態の本は`missing`へ変更する。

アーカイブ済みの本はmissing判定の対象から除外する。

スキャン結果は、検出冊数、更新冊数、新規登録冊数、missing化した冊数、アーカイブにより除外した冊数をジョブpayloadへ保存する。

## パスの安全性

ファイルを開くときは、ライブラリの`canonical_root_path`、本の`relative_path`、ページの形式別参照を使って絶対パスを組み立てる。

組み立てたパスを再度正規化し、ライブラリのルート内に収まることを検証する。

`..`、絶対パス、ドライブ文字、UNCパスなど、ライブラリ外を参照できる相対パスを拒否する。

圧縮ファイルの`entry_path`にもpath traversal検証を適用する。

APIレスポンスは、原本やページのサーバー側絶対パスを返さない。

ライブラリ設定画面だけは、登録済みの`root_path`を認証済みユーザーへ表示する。

## API

ライブラリ境界はURLへ明示する。

サーバー全体の暗黙な「現在選択中ライブラリ」をAPI処理に使用しない。

主なAPIは次のとおりとする。

```text
GET    /api/libraries
POST   /api/libraries
GET    /api/libraries/:libraryId
PATCH  /api/libraries/:libraryId
DELETE /api/libraries/:libraryId

GET    /api/libraries/:libraryId/books
GET    /api/libraries/:libraryId/books/archived
GET    /api/libraries/:libraryId/books/:bookId
PATCH  /api/libraries/:libraryId/books/:bookId/metadata
PATCH  /api/libraries/:libraryId/books/:bookId/progress
POST   /api/libraries/:libraryId/books/:bookId/archive
POST   /api/libraries/:libraryId/books/:bookId/restore

GET    /api/libraries/:libraryId/books/:bookId/pages/:pageNumber/image
GET    /api/libraries/:libraryId/books/:bookId/thumbnail

GET    /api/libraries/:libraryId/jobs
GET    /api/libraries/:libraryId/jobs/:jobId
POST   /api/libraries/:libraryId/jobs/scan
DELETE /api/libraries/:libraryId/jobs/:jobId

GET    /api/users/me/library-preference
PATCH  /api/users/me/library-preference
```

URLの`libraryId`と対象レコードの`library_id`が一致しない場合は、別ライブラリの存在を漏らさず`404 NOT_FOUND`を返す。

ライブラリが存在しない場合も`404 NOT_FOUND`を返す。

入力値の形式違反は`400 INVALID_INPUT`を返す。

対象ディレクトリが読み取れない場合は`400 INVALID_LIBRARY_PATH`を返す。

重複または包含関係にある対象ディレクトリは`409 LIBRARY_PATH_CONFLICT`を返す。

実行中ジョブによって更新または削除できない場合は`409 LIBRARY_BUSY`を返す。

## Web UI

ログイン後のアプリケーションシェルへ、選択中ライブラリを示すPrimeVue `Select`を配置する。

ライブラリが一件もない場合は、通常の本一覧の代わりに「ライブラリを追加」ボタンを表示する。

ライブラリが存在して本が0冊の場合は、選択中ライブラリのスキャン操作を表示する。

ライブラリ登録フォームは、名前とサーバー側絶対パスだけを受け取る。

Web UIではブラウザーのフォルダーピッカーを使用しない。

ブラウザーのフォルダーピッカーはHonoサーバー側の絶対パスを取得できないためである。

Tauri版では将来ネイティブのフォルダーピッカーを入力補助として追加できるが、本変更ではWeb UIと同じ文字列入力を使用する。

ライブラリ管理画面は次の操作を提供する。

- ライブラリ登録
- 名前と対象ディレクトリの編集
- スキャン開始
- ライブラリ削除

ライブラリ削除は、ライブラリ名を含む確認ダイアログを表示してから実行する。

確認文は、SQLite内の蔵書情報とサムネイルを削除し、原本には触れないことを短く示す。

本の詳細画面は「アーカイブ」を提供する。

アーカイブ一覧は「復元」を提供する。

本の削除操作は表示しない。

画面内の説明文は最小限とし、ラベル、状態、操作結果だけを表示する。

製品の魅力を説明する販促調の文章は追加しない。

フォームは可視ラベル、`name`、`required`、エラーとの`aria-describedby`関連付けを持つ。

処理結果は色だけに依存せず、テキストとアイコンで示す。

ライブラリ切替時は、選択中ライブラリに依存する本一覧、ジョブ、検索条件を再取得する。

実行中ジョブは切替後も元のライブラリで継続する。

## Desktop Manager

Desktop Managerは共通サーバーの起動、停止、状態確認、Web UIを開く操作を担当する。

Desktop Managerはライブラリの蔵書処理とスキャンを直接実行しない。

初期設定フォームから`DataDir`とCollection Root入力を削除する。

ライブラリ管理はWeb UIへ統一する。

Tauri開発時は`pnpm dev`だけでWeb frontendを表示するのではなく、Tauri起動コマンドからデスクトップウィンドウを起動する既存方針を維持する。

## 設定移行

旧`config.json`に`dataDir`または`setupComplete`が存在しても、未知フィールドとして無視する。

次回の設定保存時に旧フィールドを書き戻さない。

本変更は、利用者が既存の蔵書SQLiteを削除して初期設定をやり直す前提とする。

旧`dataDir/bookcafe.sqlite`から新しい共通SQLiteへの自動データ移行は行わない。

自動変換では、複数Collection Rootを一つのライブラリへまとめるか、別ライブラリへ分割するかを一意に決められないためである。

原本ファイルは移行の対象ではなく、ライブラリ登録後の再スキャンで読み取る。

## エラー処理

ファイルシステムのエラーは、内部パスやスタックトレースをAPIレスポンスへ含めない。

サーバーログは、エラーコード、操作種別、`library_id`、安全に出力できる原因を記録する。

ライブラリの対象ディレクトリが一時的に利用できない場合は、ライブラリ登録を削除せず、スキャンジョブを`failed`へ変更する。

一つの本の解析失敗は、その本を`error`として記録できる場合に記録し、他の候補のスキャンを継続する。

ライブラリ削除と対象ディレクトリ変更は、実行中ジョブとの競合を明示的に拒否する。

予期しない例外はHonoのglobal error handlerで`500 INTERNAL_ERROR`へ変換する。

## テスト方針

実装は小さい失敗テストから始め、対象機能を通す最小実装を追加する。

### 設定

- 既定の状態ディレクトリから共通SQLiteパスを解決する
- 旧`dataDir`と`setupComplete`を読み飛ばす
- 設定保存時に旧フィールドを書き戻さない

### データベース

- ライブラリ名と対象ディレクトリの一意制約
- 親子関係にある対象ディレクトリの拒否
- `(library_id, relative_path)`による本の更新
- ライブラリルート変更後も本IDが変化しない
- ライブラリ削除時の関連レコード連鎖削除
- 本のアーカイブと復元
- アーカイブ済み本の通常一覧除外
- ユーザーごとの読書進捗
- ページ一覧の原子的な置換
- ページ数減少時の読書位置丸め

### スキャナー

- ライブラリルートから本と画像の相対パスを生成する
- アーカイブ済み相対パスを解析前に除外する
- 画像フォルダー、圧縮ファイル、PDF、EPUBのページ順
- キャンセル時の協調停止

### API

- 初期設定がライブラリなしで完了する
- 本が0冊の場合にsample bookを返さない
- 認証済みユーザーだけがライブラリを管理できる
- ライブラリ登録、更新、削除、一覧
- ライブラリ境界を越えた本とジョブへの`404`
- ライブラリ単位のスキャン
- 実行中ジョブがあるライブラリの更新と削除拒否
- 本のアーカイブと復元
- アーカイブ済み本のスキャン除外
- ページ画像のパストラバーサル拒否

### Web UI

- ライブラリ未登録時の空状態
- ライブラリ登録フォームの検証とエラー表示
- ライブラリ切替によるデータ再取得
- スキャン開始とジョブ進捗
- ライブラリ削除確認
- 本のアーカイブと復元
- キーボード操作とフォーカス復帰
- 狭い画面でのフォームと操作列

### Desktop Manager

- 初期設定payloadに`dataDir`とCollection Rootを含めない
- 初期設定完了後にWeb UIを開ける
- サーバー起動設定が共通状態ディレクトリを使用する

## 完了条件

- SQLiteファイルが共通状態ディレクトリの一つに集約されている
- Better Authユーザーとすべてのライブラリが同じSQLiteを使用している
- Web UIから複数の名前付きライブラリを登録、切替、編集、スキャン、削除できる
- 各ライブラリが一つの対象ディレクトリを持つ
- 本とページが絶対パスではなくライブラリ相対パスを保存する
- ライブラリルート変更後も相対パスが同じ本のIDとメタデータが維持される
- 本をアーカイブすると通常一覧とスキャンから除外される
- アーカイブ一覧から本を復元できる
- 本の削除操作が存在しない
- ライブラリ削除が原本ファイルへ触れない
- ページ画像APIがライブラリ外のパスを読めない
- 初期設定がライブラリ登録なしで完了する
- UI内の説明文が操作に必要な最小限へ抑えられている
- 対象packageのtest、lint、typecheck、formatが成功する
- Web UIの主要フローを実ブラウザーで確認できる
